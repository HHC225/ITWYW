# ITWYW

### Is This What You Want?

[English](README.md) · [한국어](README.ko.md) · [日本語](README.ja.md) · [繁體中文](README.zh-TW.md)

**원하는 기능을 자신의 말로 설명해 보세요. 기능의 이름과 쉬운 설명을 알아보고, 생각한 기능이 맞는지 간단히 확인할 수 있습니다.**

ITWYW는 앱이 어떻게 동작하면 좋을지는 알지만 개발 용어는 모르는 사람을 위한 AI 에이전트 스킬입니다. 프런트엔드 상호작용, 백엔드 동작, 인프라 요구 사항을 다룹니다. 특히 초보자와 자연어로 AI에 지시하며 개발하는 사람에게 유용합니다.

> “버튼을 누르면 오른쪽에서 무언가가 밀려 나왔으면 좋겠어요.”
>
> **드로어(측면 패널):** 화면 가장자리에서 패널이 열리며 추가 옵션을 보여 줍니다.
>
> “오른쪽에서 열리는 패널을 원하시는 건가요?”

## 주요 기능

- 설명한 동작이 명확하면 **가장 가능성 높은 기능 하나**를 찾아냅니다.
- 설명을 여러 가지로 해석할 수 있으면 **최대 세 가지 후보**를 제시합니다.
- 개발 경험이 없어도 이해할 수 있도록 각 후보를 짧고 일상적인 말로 설명합니다.
- 움직임이나 보이지 않는 처리 과정을 이해하는 데 도움이 되면 작은 전후 비교 표나 텍스트 순서를 활용합니다. 이미지 생성은 필요하지 않습니다.
- **답하기 쉬운 확인 질문 하나**를 한 뒤, 확인된 동작을 이후 대화에 반영합니다.
- 사용자의 언어 또는 사용자가 명시적으로 요청한 언어로 답합니다. 스킬과 참조 자료는 영어로 작성되어 있습니다.
- 기능을 파악하는 일과 구현 방식을 선택하는 일을 구분합니다. “빠르게 만들어 주세요”라는 요청을 곧바로 특정 데이터베이스, 프레임워크, 클라우드 서비스에 대한 추천으로 바꾸지 않습니다.

## 예시

| 사용자가 할 법한 말 | ITWYW가 찾아내는 데 도움을 줄 수 있는 개념 |
| --- | --- |
| “질문을 누르면 바로 아래에 답이 펼쳐졌으면 좋겠어요.” | 아코디언 또는 펼치기/접기. |
| “작은 상자가 떴으면 좋겠어요.” | 동작에 따라 모달 대화상자, 팝오버 또는 토스트. |
| “스크롤해도 메뉴가 맨 위에 계속 있었으면 좋겠어요.” | 계속 표시되는 헤더. 필요하면 고정 위치 방식과 특정 지점부터 붙어 있는 방식을 구분합니다. |
| “구매 버튼을 두 번 눌러도 주문은 하나만 만들어 주세요.” | 멱등성을 이용한 중복 주문 방지. |
| “파일 주인만 파일을 열 수 있게 해 주세요.” | 권한 부여 및 소유권 확인. |
| “페이지를 계속 사용하는 동안 보고서를 처리해 주세요.” | 진행 상태를 알려 주는 백그라운드 작업. |
| “우리 둘이 같은 문서에 동시에 글을 쓸 수 있으면 좋겠어요.” | 실시간 공동 편집. |
| “주 서버가 멈추면 사이트를 다시 사용할 수 있게 해 주세요.” | 허용할 수 있는 중단 시간에 따라 장애 조치 또는 복구. |

이는 해석의 예시이며, 미리 정해 둔 문구와 일대일로 대응시키는 규칙이 아닙니다. 스킬은 맥락과 관찰할 수 있는 차이를 활용합니다. 스크린샷은 겉모습을 보여 줄 수 있지만, 보이지 않는 서버 동작이나 애니메이션의 작동 방식을 입증하지는 못합니다.

### 변화 보여 주기

백그라운드 작업은 다음처럼 간단히 설명할 수 있습니다.

| 사용자가 요청할 때 | 작업이 진행되는 동안 | 작업이 끝나면 |
| --- | --- | --- |
| 보고서 내보내기 | 페이지 계속 사용하기 | 보고서 다운로드하기 |

요청이 모호하면 기술 용어를 잔뜩 나열하는 대신 후보 사이의 차이를 설명합니다. 정지 화면을 순서대로 보여 주어 움직임을 설명하며, 이를 실제로 실행되는 애니메이션으로 제시하지 않습니다. 실행 환경에서 더 명확한 표현을 표시할 수 없을 때는 일반 텍스트로 만든 ASCII 프레임을 대안으로 사용합니다.

## 스킬 사용하기

배포용 스킬 폴더는 **[skills/itwyw](skills/itwyw)**이며, 진입점은 **[SKILL.md](skills/itwyw/SKILL.md)**입니다.

1. 이 저장소를 복제하거나 다운로드합니다.
2. `references/`와 `agents/`를 포함한 `skills/itwyw` 폴더 전체를 에이전트에서 지원하는 스킬 디렉터리에 복사합니다. 실행 환경마다 스킬 탐색 경로와 호출 구문이 다르므로 해당 환경의 설치 지침을 따르세요.
3. 이름으로 스킬을 호출할 수 있는 환경에서는 다음과 같이 요청합니다.

   ```text
   $itwyw 스킬을 사용해 줘. 메뉴를 누르면 오른쪽에서 작은 패널이 밀려 나오게 하고 싶어.
   ```

   또는 자신의 언어로 요청하면서 ITWYW를 명시적으로 언급하세요.

이 스킬에는 애플리케이션 서버, 런타임 패키지, API 키, 이미지 생성 서비스가 포함되어 있지 않으며, 이러한 요소를 필요로 하지도 않습니다. 스킬을 읽고 따를 수 있는 에이전트는 필요합니다. 요청한 용어가 참조 자료의 범위를 벗어나거나 특정 제품의 최신 정보를 확인해야 할 때는 웹 탐색이 유용합니다.

## 참조 자료의 범위

| 영역 | 매핑 항목 수 | 다루는 내용의 예시 |
| --- | ---: | --- |
| 프런트엔드 | 113 | 레이아웃, 탐색, 폼, 표, 오버레이, 피드백, 로딩, 시각 효과, 움직임. |
| 백엔드 | 99 | 데이터, 검색, 신원, 접근 권한, 작업, 외부 연동, 알림, 청구 상태, 공동 편집. |
| 인프라 | 84 | 호스팅, 도메인, 네트워킹, 배포, 환경, 모니터링, 처리 용량, 백업, 복구. |
| **합계** | **296** | **일상적인 말로 쓴 예시 문구 592개.** |

분야별 카탈로그 10개에는 **서로 다른 1차 출처 URL 254개를 다루는 출처 항목 255개**가 있으며, **2026-10-25**에 조사했습니다. 출처에는 W3C, MDN, 공식 디자인 시스템, PostgreSQL, OWASP, OpenID, Stripe, RabbitMQ, AWS, Microsoft, Google Cloud, Kubernetes, Docker, OpenTelemetry가 포함됩니다.

이 수치는 매핑 항목의 수이며, 모든 계층에 걸쳐 개념 이름이 하나도 겹치지 않는다는 뜻은 아닙니다. 참조 자료는 계속 확장할 수 있습니다. 일상적인 표현, 짧은 설명, 질문, 상태 변화 순서는 자료를 종합하여 새로 작성했습니다. 출처의 한계와 관용적으로 쓰이는 명칭은 명시합니다.

전체 매핑, 근거의 적용 범위, 그리고 이 프로젝트의 계기가 된 프런트엔드 스크린샷 속 24개 패턴을 모두 어떻게 다루는지는 **[출처와 범위](skills/itwyw/references/sources-and-coverage.md)**를 참고하세요.

## 기여 및 검증

초보자도 이해할 수 있는 설명 방식, 최대 세 가지 후보라는 제한, 언어 선택, 확인된 사실과 가정의 구분을 유지하세요. 기능을 추가할 때는 1차 출처와 다른 기능과 구분할 수 있는 단서를 함께 추가하세요. 사용자에게 드러나는 동작이 바뀌면 네 언어의 README를 모두 확인하세요.

오프라인 검사를 실행합니다.

```bash
python3 scripts/validate.py
```

그런 다음 이 스킬을 사용하는 새 에이전트로 [evals/scenarios.md](evals/scenarios.md)의 관련 시나리오를 실행해 보세요. 구조 검사만으로 모델이 모든 설명을 항상 이해한다고 입증할 수는 없습니다.
