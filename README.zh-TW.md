# ITWYW

### Is This What You Want?

[English](README.md) · [한국어](README.ko.md) · [日本語](README.ja.md) · [繁體中文](README.zh-TW.md)

**用自己的話描述想要的功能，就能知道它的名稱、讀懂簡單的說明，並快速確認是否符合你的意思。**

ITWYW 是一項 AI 代理技能，適合知道想讓應用程式做什麼、卻不熟悉開發術語的人。它涵蓋前端互動、後端行為與基礎架構需求，特別適合初學者，以及透過自然語言指示 AI 進行開發的人。

> 「按下按鈕後，我想要有個東西從右邊滑進來。」
>
> **抽屜面板（Drawer）：** 從畫面邊緣開啟的面板，用來顯示更多選項。
>
> 「你想要的是從右邊開啟的面板嗎？」

## 功能介紹

- 描述的行為明確時，找出**一個最可能的功能**。
- 描述可能有不同意思時，提供**最多三個候選功能**。
- 用簡短、日常的語言解釋各個候選功能，不需要開發經驗也能理解。
- 如果有助於理解動態效果或看不見的處理過程，就使用簡單的前後對照表或文字步驟。不需要生成圖片。
- 提出**一個容易回答的確認問題**，再將已確認的行為延續到後續對話。
- 以使用者的語言，或使用者明確指定的語言回答。技能本身與參考資料以英文撰寫。
- 將功能辨識與實作選擇分開處理。「讓它快一點」不會自動變成對特定資料庫、框架或雲端服務的推薦。

## 範例

| 使用者可能會怎麼說 | ITWYW 可以協助辨識的功能 |
| --- | --- |
| 「點一下問題，答案就會在下面展開。」 | 手風琴式元件或展開／收合元件。 |
| 「我想要跳出一個小方框。」 | 視行為而定，可能是模態對話框、浮動提示框或短暫通知。 |
| 「捲動頁面時，選單還是要留在最上面。」 | 持續顯示的頁首；需要時會區分固定定位與捲動至特定位置後才固定的行為。 |
| 「就算我按了兩次購買，也只建立一筆訂單。」 | 利用冪等性避免重複建立訂單。 |
| 「只有檔案的擁有者可以開啟它。」 | 授權與擁有權檢查。 |
| 「我繼續使用頁面的時候，幫我處理報表。」 | 提供處理狀態回饋的背景工作。 |
| 「我們兩個人要能在同一份文件裡同時打字。」 | 即時協同編輯。 |
| 「主要伺服器停了，要讓網站恢復運作。」 | 視可接受的中斷程度而定，採用容錯移轉或復原。 |

這些是可能的解讀範例，並非預先寫死的字句比對規則。技能會根據上下文與可觀察的差異來判斷。螢幕截圖可以呈現外觀，卻無法證明看不見的伺服器行為，或動畫實際如何運作。

### 呈現變化

背景工作的說明可以簡單到像這樣：

| 你提出要求 | 處理期間 | 完成後 |
| --- | --- | --- |
| 匯出報表 | 繼續使用頁面 | 下載報表 |

遇到意思不明確的要求時，技能會解釋候選功能之間的差別，不會用大量技術名詞淹沒使用者。靜態的連續畫面是用來說明動作，不會被當成正在播放的動畫。當執行環境無法呈現更清楚的表示方式時，才以純文字 ASCII 畫格作為替代方案。

## 使用技能

可供安裝的技能資料夾是 **[skills/itwyw](skills/itwyw)**，入口檔案是 **[SKILL.md](skills/itwyw/SKILL.md)**。

1. 複製或下載此儲存庫。
2. 將完整的 `skills/itwyw` 資料夾，包括 `references/` 與 `agents/`，複製到代理支援的技能目錄。請遵循該執行環境的安裝指示；技能搜尋路徑與呼叫語法因環境而異。
3. 如果環境支援透過名稱呼叫技能，可以這樣提出要求：

   ```text
   請使用 $itwyw。我想要點選選單時，有個小面板從右邊滑出來。
   ```

   也可以用自己的語言提出要求，並明確提到 ITWYW。

這項技能不附帶也不需要應用程式伺服器、執行階段套件、API 金鑰或圖片生成服務，但需要能夠讀取並遵循技能指示的代理。如果要求的術語超出參考資料的範圍，或需要查證特定產品的最新資訊，網頁瀏覽就能派上用場。

## 貢獻與驗證

請維持適合初學者的說明方式、最多三個候選功能的限制、語言選擇，以及已確認事實與假設之間的區別。新增功能時，請附上第一手資料來源，以及可用來區分其他功能的線索。如果使用者可見的行為有所變更，請檢查全部四種語言的 README。

執行離線檢查：

```bash
python3 scripts/validate.py
```

接著使用套用此技能的新代理，實際測試 [evals/scenarios.md](evals/scenarios.md) 中的相關情境。結構檢查無法證明模型一定能理解每一種描述。

## 合併政策

**代理可以準備變更、推送已獲授權的工作分支，並開啟草稿提取要求。未取得擁有者針對該項操作的明確核准前，不得合併、啟用自動合併、繞過分支規則，或放寬審查要求。**

儲存庫中的政策檔案用來指引願意遵循規則的代理。若要實際強制執行，必須啟用 GitHub 分支保護或規則集。建議設定及其限制記載於**[儲存庫保護](docs/repository-protection.md)**。這份 README 並未宣稱，將政策檔案加入儲存庫就會啟用伺服器端保護。

## 限制

ITWYW 協助雙方在開發前對需求的意思取得共識。它不是架構核准、安全稽核、效能診斷，也不是可運作的實作。它不會從螢幕截圖推斷後端內部機制。它應保留已確認的意圖、接受更正，並在使用者回答後停止重複相同的問題。
